# Read-only spreadsheet viewer

Use the existing SheetJS parser with a virtualized DOM grid. The only added runtime dependency is [sax 1.6.1 (BlueOak-1.0.0)](https://github.com/isaacs/sax-js), which reads XLSX style IDs and freeze metadata from the already-loaded ZIP. It is maintained, dependency-free and used through its strict, namespace-aware streaming API. Legacy XLS frozen panes come from the existing CFB/BIFF stream; the viewer never writes the workbook or sends it to a conversion service.

## Behaviour and limits

- Sticky column letters and row numbers, file dimensions, hidden rows/columns, merges, frozen rows/columns (released on an axis where they would cover more than half the view, so the sheet always scrolls), viewport-filling blank cells, bottom sheet tabs, click/drag/Shift selection, keyboard movement and escaped TSV copy. Only visible cells are mounted; the 1,000-row cap is removed.
- `SpreadsheetFileView` accepts optional `initialSheet` and `initialSelection` (A1 cell or range). It adds no link syntax. The value bar exposes the complete raw value or formula; the grid shows formatted cached results.
- XLSX supports available bold, italic, font name/size/colour, solid fill, horizontal/vertical alignment and explicit wrapping. Unwrapped text keeps one line and overflows into empty neighbours; occupied or merged neighbours stop it. Cell borders are drawn with their line style and colour. The sheet is always white with black text, in light and dark mode; the value bar and tabs follow the Jaz theme. Fonts must exist on the client; column character widths are multiplied by the digit width of the workbook's default font as the client renders it, so text fits its column when a fallback font is used.
- XLS supports SheetJS-exposed values, number/date text, merges, dimensions and solid fills, plus BIFF frozen panes. Its font/alignment/wrap metadata is not fully exposed by SheetJS CE. CSV preserves text/leading zeroes and has no workbook formatting. [SheetJS documents these extraction limits](https://docs.sheetjs.com/docs/api/parse-options/).
- Cached formulas are displayed, never recalculated. Conditional formatting, rich-text runs, diagonal borders, images/charts, rotation and independent split-window views are outside this viewer. XLS frozen panes use the [BIFF Window2 flag](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/80576ec8-e7f0-4c99-90a7-d850587bc97b) and [Pane coordinates](https://learn.microsoft.com/en-us/openspecs/office_file_formats/ms-xls/9dcaa80b-6315-4aea-a802-872ccd4e8d1b), rather than treating ordinary splits as freezes.

## Verification

- Both supplied tender workbooks parsed without source-byte changes: PDG has three sheets (21/19/25 merges); Adani has one sheet with seven frozen rows and three frozen columns. Real light/dark renders and Adani's Wingdings ticks were inspected in the integrated browser.
- Browser checks covered merged keyboard selection, drag selection/native TSV copy, complete value/formula display, initial sheet/range selection, and stable frozen headers after scrolling both axes. A 50,000-row CSV selected row 40,000 with about 510–525 mounted cells; sampled React renders took about 3ms in a 960px panel.
- Final sax-based spreadsheet tests pass: nine tests and 39 assertions covering XLSX/XLS/CSV, styles/source immutability, dimensions, hidden rows, merges, freeze-versus-split metadata, selection/copy, overflow and virtualization. Typecheck, focused lint and web build pass. The initial broad test run passed 503 tests with four Electron import failures; installing the existing local Electron runtime unblocked all four files, whose nine tests then passed through hidden harnesses.
- Thermo-nuclear self-review applied: separate parsing/BIFF/geometry/rendering responsibilities, memoized visible cells, no empty text subtrees, unique cell IDs across frozen panes, and merged-cell keyboard movement.
